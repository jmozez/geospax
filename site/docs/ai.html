#AI in GeoSpaX

GeoSpaX's AI features are optional and run where you choose. Nothing is sent anywhere until you pick a model, and with Ollama nothing leaves your computer.

Feature What it does Where it runs
Ask (right pane) Answers questions about your data in plain words, selects features, starts recipes Ollama on this computer, any OpenAI-compatible server, or Claude with your API key
MCP server (geospax-server mcp) Gives AI assistants (Claude Desktop, Claude Code, editors) GeoSpaX's tools On this computer; the assistant you connect decides where its model runs
Satellite embeddings (Imagery › Embeddings) Finds places like your samples, groups the landscape, classifies from labelled points, maps change between years On this computer; the embeddings are read once from a public copy
Your own model (Imagery › Detect objects) Runs an ONNX object-detection or segmentation model you add over an image On this computer; GeoSpaX ships no model

#1. Ask

Open Analysis › Ask, the Ask tab of the right pane, or right-click a layer › Ask about this layer…. Type a question, for example:

  • What layers do I have, and what is in them?
  • How many survey sites are above 2000 m? Select them.
  • Which reserve is the largest? Zoom to the reserves.
  • Make hot spots of the incidents. (runs the recipe)

The assistant does not guess. It looks at your data through the same tools the app uses and gives figures only from what those tools return. Under each answer, Looked at the data N times lists every tool it called, with the layer and the filter. Selections and zooms it asks for happen on the map, and selected features show in the attribute table.

#Its tools

Tool What it does
list_layers Layers (id, geometry, feature count, fields and types, definition query) and rasters
describe_field Min, max, mean and quantiles of a number field; the most frequent values of a text field
query_features Up to 50 attribute rows, filtered with a SQL WHERE clause and sorted, plus the total count
select_features Selects features with a WHERE clause (highlighted on the map)
zoom_to_layer Zooms the map (Ask only)
list_recipes, run_recipe, get_run Lists the workflows, starts one, follows it

Recipes that run Python or R code are never started by the assistant. Start those yourself from the Automate pane.

#Choosing the model

Click Model… in the Ask pane, or Analysis › Model….

Choice Set up Privacy
Ollama (on this computer), the default Install from ollama.com, then ollama pull llama3.2 (or qwen2.5, llama3.1, or any model that supports tools). Address: http://127.0.0.1:11434. Nothing leaves this computer.
OpenAI-compatible server LM Studio (http://127.0.0.1:1234), llama.cpp server, vLLM, or a cloud provider that speaks /v1/chat/completions. An API key only if the server needs one. A local server keeps everything local. A cloud server receives your question and what the tools return.
Claude (your API key) A key from console.anthropic.com. Model claude-opus-5-5 (default and most capable), claude-sonnet-5-5 (faster), or claude-haiku-5-5 (cheapest). Your question and what the tools return (layer names, field values) are sent to Anthropic.

Save and list models asks the server which models it has. The key is stored in ai.json in the GeoSpaX state folder, readable only by your user account. It is never sent back to the browser. Tick Forget the saved key to remove it.

Small local models answer simple questions well. For long multi-step questions, use a larger model (qwen2.5:14b, llama3.1:70b) or Claude. With Claude on the Opus 5.5, Fable 5.1, or Sonnet 5.5 models, a request Claude declines is retried on another Claude model, and you are told if it was still declined.

#API

Route
GET /api/ai/settings {provider, url, model, has_key, tools}; the key itself is never returned
PUT /api/ai/settings {provider: "ollama"|"openai"|"anthropic", url, model, key?}; omit key to keep it, "" to remove it
GET /api/ai/models The models the configured server offers: {models, error}
POST /api/ask {question, history: [{role, text}]} → {answer, steps: [{tool, args, ok, error?}], actions: [{kind: "select"|"zoom"|"run", …}]}; 502 with error when the model server fails

#2. MCP server

geospax-server mcp serves GeoSpaX's tools to any Model Context Protocol client over stdio. These are the tools above except zoom_to_layer, which needs the app. It opens your data folders like the app does, but without the web server, device watching or triggers. Only MCP messages go to stdout; notes go to stderr.

Claude Code

claude mcp add geospax -- geospax-server mcp --data ~/GIS

Claude Desktop (claude_desktop_config.json)

{
  "mcpServers": {
    "geospax": {
      "command": "geospax-server",
      "args": ["mcp", "--data", "/home/me/GIS"]
    }
  }
}

On Windows, use the full path, e.g. "C:\\Program Files\\GeoSpaX\\geospax-server.exe", and a Windows data path.

Options: --data DIR (repeatable), --state-dir DIR (default <first data folder>/.geospax, shared with the app, so recipes and runs are the same), --recipes DIR, --threads N.

Tool errors come back as results with isError: true, so the assistant can correct its request (a wrong field name, for example). Results longer than 12,000 characters are cut, and the cut is marked.

#3. Satellite embeddings

Google DeepMind's AlphaEarth Foundations sums up a whole year of Sentinel-1 radar, Sentinel-2 and Landsat imagery, elevation, and climate for every 10 m pixel on land, as 64 numbers (an embedding). Places that look and behave alike over the year get alike embeddings. So a handful of samples is enough to map a land-cover type, a few groups describe a landscape, and comparing two years shows change. GeoSpaX reads the embeddings for your area only, from the public copy on Source Cooperative, and does all the analysis on your computer.

Open Imagery › Embeddings (or Similar places, Group landscape, Classify, Change). Choose the area (the map view, or around a layer), the year, and what to do:

Task You give You get
Look at the embeddings an area Three of the 64 axes as red, green and blue: alike places get alike colours
Find places like my samples a point layer on the kind of place you want Similarity to the samples on every pixel (1 = alike), and the area at ≥ 0.9
Group the landscape the number of groups k groups of alike landscape (k-means), for you to name from what you know
Classify from labelled samples points with a class field A class map, the area per class, and leave-one-out accuracy
Change between two years two years How much each pixel changed (1 − similarity), and the changed area

Each task becomes a recipe run, with a map, a report and the citation in its methods. Two of them are also in the Toolbox, and the Ask assistant can run them: Places like my samples (embeddings-similar-places) and Classify from labelled samples (embeddings-classify). The steps are listed in AUTOMATION.md.

Good to know

  • The data covers 2017–2025, on land and coastal waters. The default year is 2024.
  • An area can be up to 60 km a side. Above about 20 km it is read coarser than 10 m, using the dataset's averaged overviews, to stay under 4 million pixels.
  • The first time a UTM zone and year is used, GeoSpaX reads that zone's file list, about 490 files at 2 KB each (a few seconds), and keeps it in <state>/aef/. A 4 km area of one year then reads in about 10 s.
  • Accuracy from leave-one-out is optimistic when the samples sit close together. Check the map with independent points.
  • Change in the embeddings means the year looked different: clearing, gardens, floods, building, but also an unusually wet year. Look at imagery before naming it.
  • Credit: "The AlphaEarth Foundations Satellite Embedding dataset is produced by Google and Google DeepMind." (CC-BY 4.0). It is added to the methods and the map credits automatically.
  • A mirror or a local copy in the same layout works too: set GEOSPAX_AEF_BASE to its address or folder.

#4. Your own model: object detection and segmentation

Imagery › Detect objects runs a model you add over an image, on your computer. An image is a drone orthophoto, aerial photo or satellite image in a data folder. Two kinds of model work:

Model Output it must have You get
Object detection: YOLOv5, YOLOv8, YOLO11 and models with the same output [1, 4+classes, boxes] (v8/11), [1, boxes, 5+classes] (v5), or [1, boxes, 6] boxes already decided (x0, y0, x1, y1, score, class) A polygon layer: one box per object with class, score and area_m2
Segmentation (U-Net, DeepLab, SegFormer exported with a per-pixel output) [1, classes, height, width], or one channel for yes/no A class raster with the area of each class

Adding a model. Use Imagery › Models…, choose the .onnx file, and give its classes (read from the file when it has them, as Ultralytics exports do), its licence and where it comes from. Export a YOLO model with yolo export model=yourmodel.pt format=onnx, or PyTorch with torch.onnx.export. GeoSpaX ships no model. Many popular pretrained weights have licences of their own: Ultralytics YOLO is AGPL-3.0 or needs a commercial licence, and SAM is Apache-2.0. Some are trained on data with other terms. The licence you state is printed in the methods of every report made with the model; without one the report says "licence not stated".

How it runs. The image is read in tiles of the model's input size (512 px for models of any size), at the image's own resolution. Use imagery close to the resolution the model was trained on. Values are divided by 255 for 8-bit images and by 10,000 for 16-bit ones; per-band mean/std, other bands (bands: [4, 3, 2]) and other scaling can be set per model or per run. Detection tiles overlap by 1/8. Overlapping boxes of a class are merged (non-maximum suppression, IoU 0.45), and boxes scoring below 0.25 are dropped. The model is data, not code: GeoSpaX evaluates it with tract (pure Rust), so nothing in the file runs, and there is no Python or runtime to install. On a laptop CPU a small YOLO model takes roughly 0.1–0.5 s per 640 px tile.

In recipes the step is ai.detect (AUTOMATION.md). The models API is GET /api/models, POST /api/models?name=FILE.onnx, PUT /api/models/NAME (labels, licence, source, task, bands, scale, mean, std) and DELETE /api/models/NAME.

#5. Safety

  • Every tool is a call to GeoSpaX's own API. The assistant can do nothing that you could not do in the app, and nothing that runs code.
  • Field values can contain text that tries to steer the assistant. That text can at most make it call the same read-only tools or start a non-code recipe, whose results go only into the runs folder.
  • Beyond localhost, the web edition's API needs its access token (README › Security), so another device cannot use your key.
