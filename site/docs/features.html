#What GeoSpaX borrows, and how it makes each feature lazy

GeoSpaX borrows proven features from commercial and open-source GIS, remote-sensing and data-science tools. It then automates them: smart defaults, auto-chosen methods, recipes and triggers (VISION.md, AUTOMATION.md).

Rules for borrowing

  • From commercial products we borrow ideas and workflows only, through clean-room specs written from public docs. No decompiled code, copied UI assets or doc text (TECH_STACK §1).
  • From open-source tools we reuse code where the license allows. GPL/AGPL engines (GRASS, SAGA, SNAP, R, OpenDroneMap) run as separate processes ("providers"), so the GeoSpaX core stays Apache-2.0 OR MIT.

How each feature is built: N native Rust engine · G GDAL/PDAL/PROJ in-process · P provider process · R R step · Py Python step · W WASM in the web edition · AI optional LLM. Phase (see TECH_STACK §8): P1 Viewer · P2 Autopilot · P3 Field & sensors · P4 Remote-sensing & geostats autopilot · P5 Cartographer & publisher · P6 Platform. ✅ built · 🚧 started.

Plugins (1.8): one tool model that reads the manifests of five ecosystems — GeoSpaX plugin.yaml, RustGIS .rgplugin (Apache-2.0), GeoLibre plugin.json + WASI tool bundles (MIT), QGIS metadata.txt (algorithms through qgis_process) and ArcGIS Pro Config.daml + .pyt (ribbon imported, Python toolbox tools run through arcpy; the .NET assembly cannot). Runtimes: recipe, process, python, r, wasm. Each plugin reports honestly what it needs when a runtime is missing, and installing one makes it removable again (uninstall never touches a --plugins dev folder) (PLUGINS.md).

Desktop workbench (1.7): ribbon with 40 commands, dockable panes (Contents/Explorer/Project · Symbology/** Attributes**/Rasters/Devices · Automate/History/Log), command palette (Ctrl+K), paged attribute table with zoom-to-row and charts, run history, status bar, resizable and collapsible docks, Identify popups. Structure modelled on RustGIS (Apache-2.0: "everything is a command", ribbon/pane vocabulary) and GeoLibre (MIT: pane set, attribute table as a peer of the map) — patterns re-implemented in TypeScript, no source copied (THIRD_PARTY_NOTICES.md).

Built so far (automation engine v0 + Phase 2 slice 2 + sensor hub v1, October 2026):

  • AutoMap rules that explain themselves, automatic page layouts with collision-free point labels, finished PNG/SVG/PDF maps and an HTML report;
  • raster maps with relief shading, ramp and class legends;
  • recipes with device / folder / schedule / after / stac / webhook / sensor triggers (threshold, geofence);
  • SQL, buffer, hexbin and cross-validated IDW;
  • spatial statistics (1.6): Gi* hot spots with automatic scale and FDR, global Moran's I, automatic kriging with standard-error maps, native and checked against R spdep/gstat;
  • terrain (Copernicus DEM for any area, hillshade, slope, aspect, TRI/TPI, contours);
  • remote sensing (STAC search, NDVI and other indices from the newest pass that is clear over the area, true colour);
  • raster classification with areas, raster values at points;
  • GRASS and SAGA providers;
  • R steps (gstat kriging) and Python steps (point-pattern statistics);
  • the device and sensor hub: sensor-logger CSV/JSON and FIT readings, live sensors over HTTP and MQTT (OwnTracks phones too), WHO air-quality guideline checks and classes;
  • LiDAR (1.4: LAS/LAZ → DTM, DSM, canopy, buildings, tree tops) and 3D scenes (1.5: terrain block diagrams, extruded buildings, trees and point clouds → glTF, an offline viewer and a rendered picture, made by the recipes themselves).

These are marked ✅ / 🚧 in the tables below; details are in AUTOMATION.md, DEVICES.md, RESULTS §11, §12 and §13.
